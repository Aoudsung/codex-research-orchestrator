# 持久记录与续接

建立记录或提交有实质结果的工作时读取。已有项目格式优先复用；这里只给最小字段，不要求为简单任务填满所有表格。

## 信息各归其位

- `charter.md` 保存问题、用户约束的权威原文及确认状态。
- `project.md` 保存参与者、工具、执行环境、授权与资源绑定。
- `state.md` 保存当前判断、可修改决策、候选主张、未决项和下一步。
- `rounds/RNN/` 保存实际提示词、附件清单、完整答复及本轮判断。
- `implementation/` 或既有执行目录保存实现、实验协议、运行结果和验收依据。
- `worklog.jsonl` 按需索引已取得结果的工作；不替代原始材料。

目录按实际需要创建。研究文件与通用 skill 分开；新建研究不会改动技能源码。历史提示词、原始答复和验收记录保留当时版本，更正写成新记录并引用旧记录。

## 一轮记录

```markdown
# RNN：本轮问题

- 目标：要改变什么判断，为什么影响当前研究目标。
- 输入：用户约束来源、方案版本、原始材料与可读范围。
- 行动：实际使用的方法与工具；提示词、附件与原文答复位置。
- 独立性：独立分析 / 独立审阅 / 共同讨论 / 自查；实际隔离情况。
- 结果：事实、推导、条件性结论与未知分别写清。
- 证据：来源、推导、代码位置或真实执行结果；注明支持哪一步。
- 约束核对：本轮涉及的约束及具体依据。
- 反馈处理：发现 → 采纳 / 反驳 / 未决 → 理由与处理证据。
- 主张和决策变化：原判断 → 新判断，条件与反证标准。
- 审阅覆盖：方案版本、主张和实际条件；可复用记录位置。
- 进展：解决的困难、排除的候选或新增的知识。
- 下一步：行动、需要的结果及判断分支。
```

## 执行回执

```markdown
complete / partial / blocked（选择实际状态）

交付物及对应版本：
行为变化或本次执行范围：
环境、数据和影响结论的参数：
实际命令或操作步骤：
返回码或执行状态：
关键数值、单位及证据位置：
与方案的偏离、未运行项或具体阻塞：
```

没有代码版本时可用明确的方案版本和材料定位，不要求额外生成文件哈希。回执中的 complete 仅表示该工作完成，不代表研究主张成立。

## 工作索引

需要多轮协作、增量观察或跨会话续接时再启用 JSONL。主研究者在成果落盘后串行追加；参与者只提交回执。工作编号与讨论轮次分别编号，不能把“已交接”字段当作发消息授权。

一行示例，内容为虚构：

```json
{"id":"W0001","round":"R01","kind":"analysis","actor":"lead","status":"complete","question":"必要条件是否成立","result":"反例排除无条件主张，保留受限条件下的候选","evidence":["rounds/R01/record.md"],"next":"推导修订后的条件"}
```

如有真实资源消耗，可增加实际单位与依据；未知不填成零。更正新增条目并注明被更正的 id，不改写历史。不要为记账额外运行实验，也不把所有工具调用变成日志。

## 续接检查点

记录当前权威约束的位置及必要原文、草案状态、当前设计和主张、关键依据、待处理反馈、授权与预算、暂停状态、正在运行的会话或作业标识、下一步。

普通续接从检查点回到权威来源，不把摘要当作新的约束。先确认正在运行的工作，收回已有结果，再决定是否发起下一项。独立判断则使用经过隔离的输入包，不读取包含其他评价的总状态。

## 用户简报

只报告本轮改变了什么判断、依据在哪里、完成了什么和实际待决事项。没有新证据时不复述计划；等待时简短说明正在等的结果即可。最终交付须自包含，不要求用户回看过程消息。
