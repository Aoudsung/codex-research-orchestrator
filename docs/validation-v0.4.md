# v0.4.0: role and construction checks

Date: 2026-10-26. This release updates the English research protocol, six role pages, handoff guidance, and optional project fields. The setup CLI, memory types and database, and MCP protocol are unchanged. Runtime changes synchronize release version metadata only.

## Three bounded scenario walkthroughs

These are structured author walkthroughs of the final instructions, not new model-backed research or independent behavioral trials.

| Scenario | Instruction path and checked decision | Result of walkthrough |
|---|---|---|
| An original candidate meets a counterexample; a reviewer suggests a known baseline | The task table, researcher duties, and original-research method require locating the failing condition and attempting a justified reconstruction within the original object. A ruled-out route is retained as evidence. Neither a baseline fallback nor a closed finding establishes the requested contribution. Pauses and resource limits still stop work. | The original-research objective remains open until its support and contribution criteria are met; bounded reviewer or contributor work can be completed separately. |
| A reproduction meets its specified protocol and reporting requirements | The task table and shared method retain reproduction's own completion boundary. Brainstorming is optional, and original-mechanism requirements apply to original research. | The reproduction can be delivered without inventing a mechanism, opening an extra discussion, or running unrelated experiments. |
| A fact observer sees a new file whose author says work is complete | Fact-observer duties require the actual read scope, observation time, source time, and source-stated status. A file appearing or a completion claim is distinct from a completion record. Deduplication uses source and state; an unchanged check returns exactly `UNCHANGED`. | The observer reports facts without a progress rating, diagnosis, recommendation, state edit, or new monitoring loop. Interpretation belongs to an authorized optimizer. |

The role review also checked that temporary contributors do not inherit lead authority, reviewers do not replace authors, and the fact observer and optimizer have separate write and decision boundaries. Participants, models, execution environments, and intervals remain project settings.

## Publication checks

The bundled skill validator and release check passed on an isolated Linux server with exit code 0. The check covered 33 Markdown documents, 91 relative references and anchors, frontmatter and version metadata, all six role resources, the standalone skill's internal references, English text, and targeted exclusion of private project identifiers and paths. Packaging includes the referenced role pages and retains MIT licenses. The remote check directory was removed automatically on completion.

The changed project fields are optional Markdown guidance. Existing projects retain their records; `install --upgrade` continues to replace only managed package files with backups. No migration or new CLI command is introduced.

No new provider calls, client communication runs, training, or performance tests were required for this documentation change. Existing evidence is retained in [memory validation](validation.md), [bridge validation](validation-v0.2.md), [onboarding validation](validation-v0.3.md), and [live-client validation](validation-v0.3.1.md). Those results are not presented as new v0.4 tests.

The update adds explicit construction ownership and task-specific completion rules. These walkthroughs and package checks do not measure research quality, prove that agents always follow the protocol, or establish an improvement over other research systems.
